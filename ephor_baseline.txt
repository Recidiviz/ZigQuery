# Ceiling for `zig build ephor` findings. CI fails when the reported TOTAL
# exceeds this number.
#
# Ephor's own `"strict": true` / `"fail_on": "warning"` gating is deliberately
# left off in ephor.json: the tree currently reports 388 findings (mostly
# ZA305/ZA306 complexity in the transformer and driver), so flipping it on
# would fail every build from day one. A ceiling enforces the invariant that
# actually matters — no new findings — and matches how testdata/baseline.txt
# and testdata/spec_baseline.txt already gate the corpora.
#
# Lower it whenever you fix something. Raising it should be justified in the PR.
# Refresh: zig build ephor -- --summary 2>&1 | grep TOTAL
#
# 388 -> 409 when tools/gen_proto.zig started emitting encoders as well as
# decoders, and a second .fdset added src/server/proto/storage.zig.
#
# Every new finding is in a generated file: 37 in src/proto/resolved_ast.zig
# and 8 in src/server/proto/storage.zig, of which 25 are ZA301 (func-too-long)
# inside an encode/encodeInto body — a message with forty fields encodes to a
# function with forty `if`s. There is nothing to fix at a call site, and
# splitting one message's encoder across several functions would help no reader.
# The hand-written half of that change (the Writer in src/proto/wire.zig and the
# round-trip tests) adds none: `zig build ephor` reports zero findings in
# src/proto/wire.zig and src/server/proto/storage_test.zig.
