# Ceiling for `zig build ephor` findings. CI fails when the reported TOTAL
# exceeds this number.
#
# Ephor's own `"strict": true` / `"fail_on": "warning"` gating is deliberately
# left off in ephor.json: the tree currently reports 388 findings (mostly
# ZA305/ZA306 complexity in the transformer and driver), so flipping it on
# would fail every build from day one. A ceiling enforces the invariant that
# actually matters — no new findings — and matches how testdata/baseline.txt
# and testdata/spec_baseline.txt already gate the corpora.
#
# Lower it whenever you fix something. Raising it should be justified in the PR.
# Refresh: zig build ephor -- --summary 2>&1 | grep TOTAL
#
# 388 -> 409 when tools/gen_proto.zig started emitting encoders as well as
# decoders, and a second .fdset added src/server/proto/storage.zig.
#
# Every new finding is in a generated file: 37 in src/proto/resolved_ast.zig
# and 8 in src/server/proto/storage.zig, of which 25 are ZA301 (func-too-long)
# inside an encode/encodeInto body — a message with forty fields encodes to a
# function with forty `if`s. There is nothing to fix at a call site, and
# splitting one message's encoder across several functions would help no reader.
# The hand-written half of that change (the Writer in src/proto/wire.zig and the
# round-trip tests) adds none: `zig build ephor` reports zero findings in
# src/proto/wire.zig and src/server/proto/storage_test.zig.
#
# 409 -> 412 for a second SQLite virtual table
# (src/internal/function/job_rows_vtab.zig). The three are the exact three
# `info_schema_vtab.zig` already contributes, and for the same reasons: xConnect
# and xFilter have signatures fixed by SQLite's C ABI, and the ZA102 is the
# deliberate absence of an `errdefer` on the module context — create_module_v2
# invokes the destructor itself on failure, so freeing there would be a double
# free (unnest_vtab.register has exactly that bug). Everything else the new file
# raised was fixed rather than absorbed.
#
# 412 -> 502 for the BigQuery v2 REST codecs (src/server/proto/bigquery.zig),
# in two steps.
#
# 412 -> 431 landed the query path: 40 messages, JSON codecs only. 431 -> 502
# added `Job` to --roots for jobs.insert and jobs.get, which takes the closure
# from 40 messages to 166 — `JobConfiguration` covers load, extract and copy
# jobs this emulator never runs, and `JobStatistics2.MlStatistics` reaches 51
# `Model_*` messages of BQML training metadata through two fields.
#
# All ninety-two are in the generated file and are the same three checks the
# encoders already raise: ZA301 func-too-long, ZA304 too-many-branches and
# ZA302 nesting. A jsonStringify is one `if` per field and a jsonDecode is one
# switch case per field. Splitting one message's codec across several functions
# would help no reader, and there is no call site to change.
#
# Eleven ZA701 remain and cannot be wrapped: the identifier alone passes the
# limit, e.g.
# `Model_ClusteringMetrics_Cluster_FeatureValue_CategoricalValue_CategoryCount`
# at nesting depth. Everywhere a line *can* be split, the emitters split it.
#
# The hand-written half adds none: `zig build ephor` reports zero findings in
# src/server/json_pb.zig, src/server/debug_stats.zig, tools/gen_proto.zig,
# src/server/internal/types/tablerow.zig and src/server/proto/bigquery_test.zig.
502
